# Languages

The app and the server speak English and German. English is the source and the fallback.

## The app (`src/locales/`)

- Texts live in `src/locales/en.ts` and `de.ts` (vue-i18n), grouped by screen. Use `$t('group.key')` in templates and `t(...)` from `useI18n()` (components) or from `@/i18n` (code that is not a component).
- Plurals: `'{n} arrow | {n} arrows'`, called as `$t('count.arrows', n)`. In German `'{n} Pfeil | {n} Pfeile'`.
- Pieces with markup (a bold name inside a sentence) use `<i18n-t keypath="..." tag="div"><template #name><b>...</b></template></i18n-t>`.
- Functions in `src/lib` do not return sentences: they return message keys (see `account.ts`, `roleChangeWarning`) or take the words as a parameter (`describeCentre`).
- `npm test` checks that both files have the same keys, placeholders and plural forms, and that every fixed key used in the source exists.
- The language is chosen under Settings (System, English, Deutsch) and stored on the device; System follows the phone (`src/composables/useLocale.ts`). The app sends it to the server as `Accept-Language`.
- To add a language: a new file in `src/locales/`, register it in `src/i18n.ts` and `useLocale.ts`, an entry in `LANGUAGES` in `SettingsView.vue`.

German style: du, "Team" (not Verein), generic masculine for people (Trainer, Schütze), end = Passe, face = Scheibe.

## The server (`server/locale/`)

Error messages are translated by Django (`LocaleMiddleware` reads `Accept-Language`). Messages of Django and the REST framework (required field, password rules) come translated already.

- In code: `from django.utils.translation import gettext`, then `gettext("Text")`; with values `gettext("Shot %(n)s: ...") % {"n": 3}`. Not for `help_text` (that is documentation of the API, English).
- After adding or changing a text (Babel is a dev dependency):

```bash
cd server
uv run pybabel extract -F babel.cfg --ignore-dirs ".*" --ignore-dirs "*/tests" --ignore-dirs "*/migrations" -k gettext -o locale/django.pot --project=Fletchr .
uv run pybabel update -D django -i locale/django.pot -d locale
# add the German text to the table in locale/translate_de.py, then:
uv run python locale/translate_de.py
uv run pybabel compile -D django -d locale
```

The compiled `.mo` files are committed (the Docker image has no gettext tools). `pytest` fails if a text in the code is missing in the catalog, or the catalog has a text the code no longer uses.
